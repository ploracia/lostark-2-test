# Ark Lens v1 구현 보고

작업 공간은 저장소 루트입니다. 앱은 루트에 두었습니다.

## 구현과 검증

- 설계 §9의 1~6단계에서 프로젝트, 테마, 키 등록·검증·삭제, API 클라이언트와 호출 제한, 검색·공유 URL, 3분 캐시를 연결했습니다.
- 7~10단계에서 목업의 가상 픽스처와 안전한 평문 Tooltip 파서, 캐릭터 섹션 카드, 지연 호출하는 원정대 드로어를 구현했습니다. 상세 가이드 §4와 §5.1에 따라 툴팁 블록은 타입 및 제목으로 찾고, 팔찌의 여러 줄 옵션은 그룹으로 유지하며, 200 + null 및 프로필 누락은 404와 같은 상태로 표시합니다.
- 11~13단계에서 오류·로딩·빈 상태, 호출 제한 대기·취소와 1회 자동 재시도, 점검 쿨다운, 반응형 배치와 접근성, CSP와 referrer 정책을 구현했습니다.
- `npm run build`, `npm test`, `tsc --noEmit`, `npm run lint`가 모두 통과했습니다. Vitest 32개 통과, 실패 0개, 상태 스냅샷 5개입니다. `npm audit` 결과는 0건입니다.
- Orca 브라우저에서 1280px 데스크톱, 768px 태블릿, 390px 모바일 레이아웃을 확인했습니다. 390px에서 가로 넘침이 없었고, `/` 검색 포커스, 방향키 탭 이동, 드로어의 키보드 포커스 유지와 Esc 종료 후 포커스 복귀를 확인했습니다.

## 설계와의 차이와 남은 일

7단계는 지시대로 목업 SAMPLE을 API 응답 필드 형태의 합성 픽스처로 구현했습니다. 검증과 스크린샷은 개발 데모와 MSW로 수행했으며, 운영 번들에서 데모 데이터가 빠진 것을 확인했습니다. 도구 버전은 의존성 감사 결과를 반영해 Vite 6, React Router 7, Vitest 5를 사용했습니다. 14단계 프록시는 범위에서 제외했습니다.

15단계의 실키 확인 항목은 [README의 키로 확인할 것](../README.md#키로-확인할-것)에 있습니다. 유효 키 200 CORS, 레이트 헤더 노출, 누락 캐릭터 응답과 CDN, 최신 Tooltip 색상 및 옵션 파싱을 앞으로 검증해야 합니다.
